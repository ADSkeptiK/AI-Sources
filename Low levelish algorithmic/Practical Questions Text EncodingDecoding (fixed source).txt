Here is the focused, ultimate list specifically for:
Unicode, encodings, decoding algorithms, text processing internals — to the level where you can realistically implement a correct text editor core.
I’ll keep it tight and only include books/resources that directly build:
bytes → encoding detection → decode → Unicode model → edit → re-encode 
No fluff, no unrelated multimedia/security stuff.
Tier 0 — Absolute Core (must-read)
These directly answer your confusion about:
• UTF-8 vs UTF-16
• code points vs bytes
• how decoding actually works
• why text ≠ bytes
1️⃣ Unicode Demystified
Status: THE foundational book.
What it gives you:
• Unicode architecture from scratch
• Code points, planes, surrogate pairs
• UTF-8 / UTF-16 / UTF-32 encoding algorithms
• BOM, normalization, combining characters
• Why “character != byte”
After this book, your mental model of:
byte → character → glyph 
will finally be correct and stable.
This is the single most important text-encoding book ever written for programmers.
2️⃣ The Unicode Standard
Status: The authoritative reference (not casual reading).
Why:
• Defines exact encoding rules
• Grapheme clusters (critical for cursor movement)
• Normalization forms (NFC/NFD)
• Text segmentation rules
You don’t read this like a novel —
you use it as a spec manual when implementing features.
Tier 1 — Practical Text Processing & Encodings
These bridge theory → real software implementation.
3️⃣  Design Patterns : Elements of Reusable Object Oriented Software
Why here:
• Shows how to design reusable low-level modules
• Helps you architect: 
• decoder modules
• buffer abstractions
• text rope/gap buffer structures
This becomes directly useful when you implement your editor’s core.
4️⃣  Algorithms on Strings , Trees, and Sequences
Relevance: ✔ for advanced correctness
Teaches:
• String representations
• Pattern matching
• Substring logic
Important when you realize:
Text editing ≠ array of chars
It’s a complex string data structure problem.
Tier 2 — Real-world Text Engine Architecture
These explain how professional editors and engines manage text internally.
5️⃣  The Craft of Text Editing
Hidden gem. Extremely relevant.
Covers:
• Gap buffers
• Piece tables
• Ropes
• Cursor movement logic
• Undo/redo models
This is basically:
“How real text editors actually work internally”
6️⃣  Compilers: Principles , Techniques and tools
Focus:
• Low-level string manipulation
• Tokenization
• Stream-based processing
Useful for implementing decoding + editing pipeline cleanly.
Tier 3 — Rendering & Glyph Layer (optional but powerful)
Only needed if you want to go beyond plain text into real UI rendering.
7️⃣  Fonts and Encoding
This explains:
• How characters map to glyphs
• Why rendering ≠ decoding
• Font rasterization basics
Important distinction:
Unicode code point → glyph index → bitmap/vector glyph 
Minimal “Ultimate” Set (if you want the tight core)
If you only read the essentials for encoding/decoding mastery:
That combination gives you:
bytes → decoding rules → Unicode model → editor data structures → rendering pipeline 
Which is exactly the full mental chain you’ve been trying to stabilize.
Final Reality Check
After mastering these, you will understand:
• Why a file has no encoding “inside” it
• How editors decide encoding
• How bytes become Unicode characters
• Why cursor movement is not “one byte at a time”
• How to safely implement: 
• UTF-8 decoder
• text buffer model
• save/re-encode logic
At that point, writing a minimal but correct text editor core becomes realistically achievable for you as a systems programmer.
