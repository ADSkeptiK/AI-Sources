A:Good question — and this is important for how you build a practical backend knowledge base.
📘 Does Seven Databases in Seven Weeks teach MySQL?
No — it does not teach MySQL specifically.
The book’s purpose is broad architectural awareness, not teaching one product in depth. It covers seven different databases to compare models and design trade-offs, not to serve as a MySQL manual. 
What it does cover:
• PostgreSQL (relational database in depth) 
• Redis (key/value store) 
• MongoDB (document store) 
• Neo4j (graph) 
• CouchDB (document store) 
• HBase (columnar) 
• DynamoDB (managed cloud key/value) 
So relational experience in the book comes through PostgreSQL, not MySQL. 
Even though the book mentions that relational databases like MySQL are still widely used, it doesn’t teach them directly — the focus is on showing what kinds of tools and models are out there and how they differ. 
📗 If you want MySQL specifically, here are good book options
📕 For practical MySQL learning
• “MySQL Cookbook” — Practical recipes for everyday tasks
👉 Great if you want working knowledge quickly (queries, schema design, transactions).
• “SQL: The Complete Reference” — Covers SQL deeply, MySQL examples often included
👉 Very solid for learning SQL as a language, with MySQL focus.
• “High Performance MySQL” — Advanced internals & scaling
👉 Excellent once you know the basics and want depth (joins, indexes, replication, performance).
(This one is often recommended even by experienced DB pros.) 
These books teach SQL, schemas, queries, joins, transactions, indexing, and performance, which is the practical, job-ready side of databases.
📙 Why PostgreSQL in Seven Databases but not MySQL
The book chose PostgreSQL because:
• It represents the modern open-source relational model
• Its features include advanced SQL, types, and indexing paradigms
• It teaches relational concepts broadly — the same concepts apply to MySQL and others
So what you learn about PostgreSQL in the book translates directly to MySQL, just with differences in syntax and tooling around it. 
If you finish that book and then open a MySQL manual, you’ll understand most of what’s going on — the relational core is the same across both.
📍 How this fits your roadmap
Your backend book path would now look like:
➡️ HTTP & APIs (why JSON/HTTP work)
➡️ Backend design (REST, JSON contracts)
➡️ Full backend framework book (e.g., Flask, Node)
➡️ Database systems exposure — Seven Databases
➡️ Dedicated SQL/MySQL books for depth
This gives you:
• a broad conceptual landscape (Seven Databases)
• relational fundamentals that transfer to MySQL
• the ability to choose and use a specific system in real code
🧠 TL;DR
✅ Seven Databases in Seven Weeks is excellent for understanding why different database types exist
❌ It does not teach MySQL specifically
👉 For MySQL learning, get a dedicated SQL/MySQL book like:
• MySQL Cookbook
• SQL: The Complete Reference
• High Performance MySQL 
That way you get:
• conceptual mastery
• practical, hands-on skill
